afairesi

A Nix library and CLI for consistent repositories.

Library CLI Source MIT License

Define packages once. Derive builds, checks, and development environments from the repository layout, then inspect interfaces and compare changes with the CLI.

Nix library

mkFlake discovers package directories containing default.nix and connects them to Nix builds, formatting, checks, and test environments.

Connect a repository

flake.nix

{
  inputs.afairesi.url = "github:afairesi/afairesi";
  outputs = inputs:
    inputs.afairesi.lib.mkFlake { inherit inputs; };
}

Keep each package in a directory at the repository root. Track its source and supporting files with Git so Nix includes them in builds. 

project/
├── flake.nix
├── flake.lock
└── example/
    ├── default.nix
    ├── main.py
    └── test_main.py  # Optional
example/default.nix 
{ inputs, pkgs, ... }:
inputs.afairesi.lib.mkPythonPackage {
  inherit pkgs;
  executable = true;
  meta.description = "An example Python command.";
  src = ./.;
}

Define main() in main.py for an executable. Set executable = false; for a Python or Lean library.

Package conventions

Package Builder Source
Python mkPythonPackage main.py
Lean 4 mkLean4Package main.lean
HTML mkHtmlPackage index.html
LaTeX mkLatexPackage ms.tex
Generic Any derivation default.nix

The builder in default.nix selects the package conventions. Use mkPythonPackage or mkLean4Package for Afairesi's source layout and automatic test environments. Other builders, including Nixpkgs' buildPythonPackage, buildRustPackage, and Haskell builders, keep their own source layouts. Supporting filenames such as main.py do not select Afairesi conventions, and directories without a tracked default.nix are not packages.

Optional test_main.py, test_main.lean, and test_main.nix files provide checks for Afairesi Python, Afairesi Lean, and generic packages respectively. Package builds and declared passthru.tests also participate in checks. Afairesi Python and Lean packages get a <name>-test development shell. Repository-wide formatting and linting apply across package kinds. 

nix flake lock
nix fmt
nix flake check
nix build .#example
nix run .#example
nix develop .#example-test

Repository CLI

Install the CLI with Nix, or run it directly without installing.

nix profile add github:afairesi/afairesi
nix run github:afairesi/afairesi -- --help

afairesi

Read package metadata, CLI arguments, and test identifiers as JSON. Inspection reads source without executing it. It recognizes Afairesi builders and resolvable aliases; standard builders and unresolved expressions have type generic. Detailed CLI arguments and test identifiers are available for recognized Afairesi Python packages. Pass a local repository path or Git URL as the optional argument; omitting it selects the current repository. 

afairesi
afairesi ../project

Repository inspection

The afairesi_gui package opens a local browser inspector for the direct submodules registered in your home Git repository. All registered repositories load on one canvas inside nested directory boxes, such as github.com / owner / repository, arranged horizontally on desktop. Scroll to zoom around the pointer and drag to pan. Resource boxes show descriptions, languages, and collapsible sections for CLI argument metadata and readable test names. Argument names, defaults, types, choices, and subcommands are read-only. Dependency arrows connect resources within each repository. Each argument name heads its own group of indented properties. Press / to focus Find a box. Click a box name to enter that directory in the inspector; click outside the outermost box to go to its parent. The current path appears in the toolbar, and the afairesi button returns to the home overview.

Staged and unstaged interface differences from afairesi diff appear directly on resource blocks, descriptions, arguments, tests, and dependency edges, with green additions and red removals. The Diff checkbox hides unchanged content. Directory labels and compact dependency endpoints remain as context. It works together with search. Diffs refresh every ten seconds and reuse cached results while HEAD, the index, and tracked files remain unchanged. Edges describe source declarations rather than the full evaluated Nix closure. The GUI inspects source without running resource builds, programs, tests, or Nix capability checks. 

nix run .#afairesi_gui
nix run .#afairesi_gui -- --no-open --port 8765

Pass --ssh user@host or an SSH host alias to open a remote workspace in your local browser. The remote machine needs nix on its PATH and access to the package source. The launcher runs nix run github:afairesi/afairesi/<commit>#afairesi_gui remotely, using the same Git commit as the local release build and enabling the needed Nix features for the remote session. Nix fetches and builds the package as needed and reuses its store on subsequent launches; no remote profile installation is needed. Repository discovery and interface diffs run there; SSH forwards the loopback server using your existing SSH configuration and authentication. The default home is the remote user's home, and --home selects a remote path. 

afairesi_gui --ssh user@host
nix run .#afairesi_gui -- --ssh my-server --home /home/user --port 8766

The build's commit must be available on GitHub. For a development build with uncommitted changes, pass --remote-revision <full published commit> to select the remote version explicitly. Local edits are not transferred over SSH.

The selected port must be free on both machines; --port 0 chooses a local free port and uses it on both ends. Keep the launcher running. Closing it stops the tunnel and its remote workspace session.

The server listens on 127.0.0.1 and serves read-only inspection APIs.

Terminal inspection

The afairesi_tui package opens your whole home workspace as an expandable text tree with vim-style navigation. It uses the same direct registered submodules as the GUI and groups them by directory, such as github.com / owner / repository. Discovery stops at that one level of submodules. The view uses your terminal's colors, plain names, and small fold markers, with no panels or key bar. Only the home root starts expanded. Expand directories and repositories to browse branches, tracked modifications, resources, descriptions, arguments, tests, and dependencies. Missing or unreadable repositories remain visible with errors. Pass --home to select another home Git repository. 

nix run .#afairesi_tui
nix run .#afairesi_tui -- --home /home/user
nix run .#afairesi_tui -- --refresh
nix run .#afairesi_tui -- diff
nix run .#afairesi_tui -- diff --cached

Use j/k to move, h/l to collapse or expand, Space to toggle a node, g/G to jump to the first or last visible row, and q to quit. Arrow keys and Page Up/Down also work. Pan long lines with H/L and reset with 0. Use diff for unstaged changes or diff --cached for staged changes. Additions and removals appear as readable + and - rows.

Inspections and diffs are cached in $XDG_CACHE_HOME/afairesi_tui, or ~/.cache/afairesi_tui by default. Cached results are reused while HEAD, the index, tracked file metadata, and the CLI version are unchanged. Branch and tracked status are read fresh. Pass --refresh to rebuild cached results. Startup reports progress and does not scan untracked files, inspect nested submodules, or compute diffs unless requested. Slow commands time out after 30 seconds.

Interface changes

Use diff to compare interfaces in the working tree, index, or Git revisions. Pass an optional repository path and select revisions with --from and --to. Add --merge-base with both revisions to compare their common ancestor with --to. Implementation changes that leave the interface unchanged are omitted. 

afairesi diff
afairesi diff --cached
afairesi diff --from HEAD~1 --to HEAD

Tests and coverage

Run nix flake check to execute package tests alongside the repository's other checks. Python checks run the complete pytest suite, including Hypothesis properties, and produce HTML and JSON coverage reports. Coverage is informational: test failures fail the check, but there is no minimum coverage percentage. 

nix flake check
nix build .#checks.x86_64-linux.example --out-link coverage
xdg-open coverage/html/index.html

Replace example with a Python package name and x86_64-linux with your system. Building the check reuses the result from nix flake check. Hypothesis uses deterministic generation with a default budget of 100 examples per property; individual tests can override these settings.
