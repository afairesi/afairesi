afairesi

A Nix library and CLI for consistent repositories.

Library CLI Source MIT License

Define packages once. Derive builds, checks, and development environments from the repository layout, then inspect interfaces and compare changes with the CLI.

Nix library

mkFlake discovers package directories containing default.nix and connects them to Nix builds, formatting, checks, and test environments.

Connect a repository

flake.nix

{
  inputs.afairesi.url = "github:afairesi/afairesi";
  outputs = inputs:
    inputs.afairesi.lib.mkFlake { inherit inputs; };
}

Keep each package in a directory at the repository root. Track its source and supporting files with Git so Nix includes them in builds. 

project/
├── flake.nix
├── flake.lock
└── example/
    ├── default.nix
    ├── main.py
    └── test_main.py  # Optional
example/default.nix 
{ inputs, pkgs, ... }:
inputs.afairesi.lib.mkPythonPackage {
  inherit pkgs;
  executable = true;
  meta.description = "An example Python command.";
  src = ./.;
}

Define main() in main.py for an executable. Set executable = false; for a Python or Lean library.

Package conventions

Package Builder Source
Python mkPythonPackage main.py
Lean 4 mkLean4Package main.lean
HTML mkHtmlPackage index.html
LaTeX mkLatexPackage ms.tex
Nix Any derivation default.nix

Optional test_main.py, test_main.lean, and test_main.nix files provide package checks. Python and Lean packages also get a <name>-test development shell. 

nix flake lock
nix fmt
nix flake check
nix build .#example
nix run .#example
nix develop .#example-test

Repository CLI

Install the CLI with Nix, or run it directly without installing.

nix profile add github:afairesi/afairesi
nix run github:afairesi/afairesi -- --help

afairesi

Read package metadata, CLI arguments, and test identifiers as JSON. Inspection reads source without executing it. Pass a local repository path or Git URL as the optional argument; omitting it selects the current repository. 

afairesi
afairesi ../project

Local workspace

The afairesi_gui package opens a local browser workspace for the direct submodules registered in your home Git repository. All registered repositories load on one canvas inside nested directory boxes, such as github.com / owner / repository, arranged horizontally on desktop. Scroll to zoom around the pointer and drag to pan. Resource boxes show build, run, and test controls, with collapsible sections for declared CLI arguments and readable test names. Dependency arrows connect resources within each repository. Compact workspace controls and a resizable native Codex terminal float over the full-screen canvas. Codex handles slash commands, file mentions, approvals, and conversation history directly. The terminal starts in the configured home directory; use /cd to switch directories and @ to mention files. Ask Codex pastes job output into its composer for you to review and send. Staged and unstaged interface differences from afairesi diff appear directly on resource blocks, descriptions, argument controls, tests, and dependency edges, with green additions and red removals. Removed resources remain visible with disabled controls. Diffs refresh every ten seconds and reuse cached results while HEAD, the index, and tracked files remain unchanged. Dragging boxes and their text pans the canvas; argument inputs remain editable. Edges point from dependencies to consumers and describe source declarations, not the full evaluated Nix closure. 

nix run .#afairesi_gui
nix run .#afairesi_gui -- --no-open --port 8765

Pass --ssh user@host or an SSH host alias to open a remote workspace in your local browser. The remote machine needs nix on its PATH and access to the package source. The launcher runs nix run github:afairesi/afairesi/<commit>#afairesi_gui remotely, using the same Git commit as the local release build and enabling the needed Nix features for the remote session. Nix fetches and builds the package as needed and reuses its store on subsequent launches; no remote profile installation is needed. Repository discovery, builds, tests, diffs, and Codex run there; SSH forwards the loopback server using your existing SSH configuration and authentication. The default home is the remote user's home, and --home selects a remote path. 

afairesi_gui --ssh user@host
nix run .#afairesi_gui -- --ssh my-server --home /home/user --port 8766

The build's commit must be available on GitHub. For a development build with uncommitted changes, pass --remote-revision <full published commit> to select the remote version explicitly. Local edits are not transferred over SSH.

The selected port must be free on both machines; --port 0 chooses a local free port and uses it on both ends. Keep the launcher running. Closing it stops the tunnel and its remote workspace session.

The server listens on 127.0.0.1. The GUI bundles Codex from the locked Nixpkgs input, so it needs no separate installation. Codex starts automatically in the bottom terminal and uses its existing account or native sign-in. Over SSH, an unsigned-in session first runs codex login --device-auth; open its link locally and enter the displayed code. Credentials stay managed by Codex on the workspace machine. Pass --codex /path/to/codex to override the executable on that machine. Refreshing or reconnecting the browser reattaches to the same running terminal and replays its recent output. Native /resume restores saved Codex conversations after a workspace restart. Closing the launcher stops its terminal and running jobs.

Interface changes

Use diff to compare interfaces in the working tree, index, or Git revisions. Pass an optional repository path and select revisions with --from and --to. Add --merge-base with both revisions to compare their common ancestor with --to. Implementation changes that leave the interface unchanged are omitted. 

afairesi diff
afairesi diff --cached
afairesi diff --from HEAD~1 --to HEAD

Tests and coverage

Run nix flake check to execute package tests alongside the repository's other checks. Python checks run the complete pytest suite, including Hypothesis properties, and produce HTML and JSON coverage reports. Coverage is informational: test failures fail the check, but there is no minimum coverage percentage. 

nix flake check
nix build .#checks.x86_64-linux.example --out-link coverage
xdg-open coverage/html/index.html

Replace example with a Python package name and x86_64-linux with your system. Building the check reuses the result from nix flake check. Hypothesis uses deterministic generation with a default budget of 100 examples per property; individual tests can override these settings.
