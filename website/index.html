afairesi

αφαίρεση — subtraction, abstraction

Source Paper MIT License

Afairesi organizes your computing environment around one principle: satisfy the requirements with the fewest independent decisions.

NixOS defines the system, Preservation keeps declared state across reboots, and Git records your home's repository collection. Within repositories, directory names and conventional files identify packages, hosts, and tests. Afairesi's CLI maintains this structure, and its Nix library derives builds and checks from the project files. Python and Lean4 packages also receive development environments.

nix fmt repairs repository structure, stages changes, removes files outside the permitted layout, and applies formatting and potentially behavior-changing fixes. Keep supporting files in prm/ and temporary data in tmp/; review the diff and run nix flake check afterward.

Design principle

The structure above replaces repeated choices with shared rules. A repository's remote URL determines its location in your home. A package directory supplies its name, and a conventional test file registers its check. Python and Lean4 test and development environments reuse the package's dependencies.

An independent decision is something you must choose or maintain separately. Deriving a value removes that maintenance; keeping two editable copies means keeping them in sync. Shared rules also have a cost, including their implementation and exceptions. Use them when they reduce the total choices you maintain while preserving the behavior, variation, and recovery your environment needs.

The paper explains the environment's requirements, the choices behind this structure, and its limitations.

Install

The full environment shown above uses NixOS with Preservation. The CLI and project tools require Git and Nix with flakes enabled on Linux or Apple Silicon macOS.

Use this flake.nix to derive packages, checks, and hosts:

{
  inputs.afairesi.url = "github:afairesi/afairesi";
  outputs = inputs: inputs.afairesi.lib.mkFlake { inherit inputs; };
}

Development shells are generated for Python and Lean4 packages.

To install the CLI on a host managed by this flake, add to its configuration.nix (mkFlake supplies inputs): 

{ inputs, pkgs, ... }:
{
  environment.systemPackages = [
    inputs.afairesi.packages.${pkgs.stdenv.hostPlatform.system}.afairesi
  ];
}

Or start a shell with the CLI:

nix shell github:afairesi/afairesi

To manage hosted repositories as home submodules:

afairesi home init
afairesi home add https://github.com/<user>/<repo>.git

In an empty Git worktree, generate the flake above and add a package:

afairesi repo init
afairesi repo add example python

Nix packages require default.nix. The optional main.nix and test_main.nix filenames are Afairesi conventions. Import main.nix explicitly where needed. test_main.nix returns a check derivation for nix flake check; its function can request inputs, pkgs, system, pname, and packageDrv (the package being tested).
