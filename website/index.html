Differences in solutions should reflect differences in requirements.

Similar problems should have similar solutions. Eliminate differences that requirements do not justify. For afairesi, requirements concern executable behavior and declared state.

What follows

  1. Choose a canonical representation. Equivalent requirements should lead to the same arrangement, independent of how it was assembled. Shared conventions replace repeated local choices.
  2. Derive what the rules determine. Once a declaration and a shared rule determine a location, name, or registration, it needs no independent specification.
  3. Keep one source of truth. Each independent fact has one authoritative declaration; derived information follows it. This is a consequence of derivation.
  4. Return to the canonical arrangement. Applying the same rules again should make no further changes. This is the idea behind a “home” operation.

Implementation choices

The afairesi CLI and Nix flake library apply this approach across the working environment. Nix, Git submodules, and the particular naming and ordering conventions are choices that serve the principle.

System
Nix expresses builds and system configuration as code. On NixOS, impermanence or preservation makes the choice of persistent state explicit.
Home
Git submodules record a collection of repositories and their revisions. Each repository's location follows its remote: ~/host/owner/repository/.
Repositories
Package and host files determine flake outputs. Shared conventions derive builds and checks from those files, avoiding separate registrations.
Source
Canonicalize structures whose order carries no meaning. Comment removal is an additional policy: executable code and declared state carry the specification, so explanatory comments are removed from managed source files.
Install on NixOS

Use afairesi to generate your flake outputs. Keep your existing inputs for impermanence, preservation, and other modules: 

{
  inputs = {
    afairesi.url = "github:afairesi/afairesi";
    preservation.url = "github:nix-community/preservation";
  };
  outputs =
    inputs:
    inputs.afairesi.lib.mkFlake {
      inherit inputs;
    };
}

mkFlake discovers my-host/configuration.nix and passes inputs to it automatically. It uses afairesi's nixpkgs input unless you provide your own. Keep your host's hardware imports, platform, and persistence settings, and include the CLI in that module: 

{ inputs, pkgs, ... }:
{
  nix.settings.experimental-features = [ "nix-command" "flakes" ];
  environment.systemPackages = [
    inputs.afairesi.packages.${pkgs.stdenv.hostPlatform.system}.afairesi
  ];
}

In a Git repository, stage new configuration files so Nix can see them. Apply from the directory containing your configuration's flake.nix: 

git add flake.nix my-host/
sudo nixos-rebuild switch --flake .#my-host

With impermanence or preservation, keep your home directory on a persistent filesystem or bind-mount the home directory from persistent storage. This keeps ~/.git/, ~/.gitignore, ~/.gitmodules, and repository checkouts together across reboots. Managed files and repository path components must not be symlinks.

Other systems: home and repo

On other systems with Nix, use afairesi home and afairesi repo independently. Enable these features in ~/.config/nix/nix.conf: 

experimental-features = nix-command flakes

Run without installing:

nix run github:afairesi/afairesi -- repo --help

Or install for your user (Nix 2.30 or newer):

nix profile add github:afairesi/afairesi
