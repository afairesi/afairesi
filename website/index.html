afairesi

Source MIT License

Satisfy the requirements with the fewest independent decisions.

An independent decision is something that must be specified because existing declarations and rules do not determine it. Requirements concern executable behavior and declared state. Shared rules replace repeated choices: similar problems, similar solutions.

The inspiration is the method of stationary action: specify constraints and a governing criterion, then derive the rules. Afairesi's criterion is fewer independent design decisions.

What follows

  1. Derive before declaring. A determined value needs no independent specification. This gives each independent fact one source of truth.
  2. Share rules. Replace repeated local choices with common conventions. Count the machinery and exceptions those conventions introduce too.
  3. Normalize repeatably. Fixed declarations and conventions determine a canonical arrangement. Restoring it again should change nothing. Scoped repairs are implemented; a whole-environment “home” operation remains a design goal.

Deriving the afairesi rules

For each rule, preserve the requirement, remove independently maintained choices, and account for the convention introduced. The CLI and Nix flake library apply this from system configuration through home metadata to repository, package, and test names.

Construction
Builds and hosts need reproducible environments. Nix/NixOS derives them from declared dependencies and configuration, replacing separate setup procedures with shared builders.
Persistence
Recovery needs surviving state. Declare it through impermanence or preservation and reconstruct the rest, replacing dependence on a machine's accumulated history.
Repositories
Independent histories and recorded revisions motivate Git submodules. Remotes determine ~/host/owner/repository/; gitlinks record commits. Updating revisions is separate from restoring the recorded state.
Discovery
Conventional package, host, and test files determine outputs and checks. Package directories determine command names. Resource identities and test names remain inputs; their registrations follow shared rules.
Dependencies
Tests and development need the package's dependencies. Derive their environments from those dependencies and shared test tools, removing separate dependency lists.
Tracked state
Derive repository .gitignore entries from the permitted layout. Use prm/ for supporting files and tmp/ for temporary data: two shared locations replace repeated placement and tracking decisions.
Representation
Shared formatting removes local presentation choices. Sort order-insensitive source, home submodule sections, and whitelist entries. Omit default-valued settings only when their omission preserves behavior under the pinned configuration.
Comments
Executable code and declared state carry the specification. Remove independently maintained explanatory comments; tool-interpreted directives must be considered for their behavioral effects.

Nix, alphabetical order, filenames, and the persistence module are chosen realizations. The principle guides their comparison; it does not uniquely select them or prove a global minimum.

Install on NixOS

Use afairesi to generate your flake outputs. Keep your existing inputs for impermanence, preservation, and other modules: 

{
  inputs = {
    afairesi.url = "github:afairesi/afairesi";
    preservation.url = "github:nix-community/preservation";
  };
  outputs =
    inputs:
    inputs.afairesi.lib.mkFlake {
      inherit inputs;
    };
}

mkFlake discovers my-host/configuration.nix and passes inputs to it automatically. It uses afairesi's nixpkgs input unless you provide your own. Keep your host's hardware imports, platform, and persistence settings, and include the CLI in that module: 

{ inputs, pkgs, ... }:
{
  nix.settings.experimental-features = [ "nix-command" "flakes" ];
  environment.systemPackages = [
    inputs.afairesi.packages.${pkgs.stdenv.hostPlatform.system}.afairesi
  ];
}

In a Git repository, stage new configuration files so Nix can see them. Apply from the directory containing your configuration's flake.nix: 

git add flake.nix my-host/
sudo nixos-rebuild switch --flake .#my-host

With impermanence or preservation, keep your home directory on a persistent filesystem or bind-mount the home directory from persistent storage. This keeps ~/.git/, ~/.gitignore, ~/.gitmodules, and repository checkouts together across reboots. Managed files and repository path components must not be symlinks.

Other systems: home and repo

On other systems with Nix, use afairesi home and afairesi repo independently. Enable these features in ~/.config/nix/nix.conf: 

experimental-features = nix-command flakes

Run without installing:

nix run github:afairesi/afairesi -- repo --help

Or install for your user (Nix 2.30 or newer):

nix profile add github:afairesi/afairesi
